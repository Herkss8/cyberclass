Советы по безопасности

Пароли

Используй менеджер паролей, уникальный пароль для каждого сервиса и двухфакторную аутентификацию. Код из SMS никому не сообщай.

Фишинг

Проверяй адрес отправителя и домен сайта, а не только название. Срочность и угрозы часто используют, чтобы не дать время подумать. Заходи на сервис через закладку.

Обновления

Обновления закрывают известные уязвимости. Устанавливай их через настройки системы и приложений.

Справочник

Понятия из учебной литературы по информационной безопасности и криптографии, изложенные кратко.

Конфиденциальность, целостность, доступность (CIA)

Базовая триада свойств защиты информации. Конфиденциальность означает доступ только для авторизованных субъектов, целостность гарантирует неизменность данных без санкции, доступность обеспечивает доступ к ресурсам в нужное время. Подмена суммы в платёжке без кражи данных нарушает целостность.

Хеширование паролей

Криптографическая хеш-функция должна быть стойкой к поиску прообраза и коллизий. Для паролей применяют медленные функции (bcrypt, scrypt, Argon2) с уникальной солью для каждого пользователя. Соль затрудняет использование радужных таблиц, а медленность увеличивает стоимость перебора.

Режимы блочного шифрования

Режим ECB шифрует каждый блок независимо. Одинаковые блоки открытого текста дают одинаковые блоки шифротекста, поэтому структура данных просвечивает. Режимы с цепочкой блоков и вектором инициализации (например, CBC или CTR с правильным nonce) лишены этого недостатка.

Симметричное и асимметричное шифрование

Симметричные алгоритмы (например, AES) быстры, но требуют безопасной передачи ключа. При попарном обмене между n участниками нужно n(n-1)/2 ключей. Асимметричные схемы (RSA, ECC) используют пару ключей и применяются для обмена симметричным ключом в гибридных схемах.

Инфраструктура открытых ключей (PKI)

Удостоверяющий центр подписывает сертификаты, связывая открытый ключ с владельцем. Доверие строится по цепочке сертификатов до доверенного корня. Самоподписанный сертификат не подтверждён доверенным центром, поэтому браузер предупреждает о нём.

Двухфакторная аутентификация

Факторы делятся на три группы: знание (пароль), владение (телефон, ключ, приложение-генератор) и биометрия. Два фактора из разных групп повышают защиту. Коды из SMS уязвимы к перехвату, поэтому приложения-генераторы и аппаратные ключи надёжнее.

Принцип наименьших привилегий и Zero Trust

Пользователь получает только необходимые права. Модель Zero Trust проверяет каждый запрос отдельно и не доверяет субъекту только из-за его местоположения в сети. В быту это означает отзыв ненужных разрешений у приложений и доступов у сторонних сервисов.

Реагирование на инцидент

Этапы: подготовка, обнаружение, сдерживание, устранение последствий, восстановление и анализ причин. При угоне аккаунта сначала меняют пароль и завершают чужие сессии, сохраняют переписку и уведомления, затем разбираются в причине.
